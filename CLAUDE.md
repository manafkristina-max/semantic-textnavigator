# Semantic TextNavigator — правила работы над проектом

## Роли
Пользователь — Product Owner. Задачи приходят простым русским языком, без указания файлов и функций.
Claude самостоятельно выполняет полный цикл, не просит пользователя редактировать файлы, запускать команды или искать ошибки.

## Цикл для каждого запроса
Запрос → Анализ → Изменение кода → Тесты → Исправление ошибок → Запуск → Проверка в браузере → Отчет.

1. Определить, какие компоненты затронуты (см. карту ниже), прочитать их код.
2. Внести изменение в файлы проекта (не инструкции, не заглушки).
3. Сохранить обратную совместимость; существующие тесты должны оставаться зелеными.
4. Добавить/обновить pytest-тесты на новое поведение.
5. Запустить `./run.sh test` (или `.venv/bin/python -m pytest -q`). Не утверждать, что тесты пройдены, без запуска.
6. Убедиться, что приложение доступно на http://localhost:8501 (Streamlit перезапускает страницу сам — `runOnSave = true`;
   если сервер не запущен — `preview_start` с конфигурацией `textnavigator` из `.claude/launch.json`).
7. Проверить пользовательский сценарий в браузерной панели (загрузка → «Проанализировать» → нужная вкладка).
   Файлы в браузерной панели загружаются через галочку «папка documents» (перетаскивание файлов агентом не автоматизируется).
   Таблицы `st.dataframe` рисуются на canvas — их проверять скриншотом, остальной текст — через `get_page_text`/innerText.
   UI-поведение, которое легко сломать, закреплять тестом `streamlit.testing.v1.AppTest` (см. `tests/test_questions_and_app.py`).
   Новый тест сначала убедиться, что он падает без исправления, затем — что проходит с ним.
8. Не задавать уточняющих вопросов, если запрос понятен; разумные решения принимать самостоятельно и перечислять в отчете.

## Публикация
- Публичная версия: https://semantic-textnavigator.streamlit.app (Streamlit Community Cloud, Python 3.13).
- Исходники: https://github.com/manafkristina-max/semantic-textnavigator, ветка `main`.
- Streamlit Cloud пересобирает приложение сам после `git push` в `main` (около 1 минуты).
- Коммит и push — только по просьбе пользователя и только после зеленых тестов. После push открыть публичный адрес
  и проверить изменение там же, где проверялось локально.

## Формат ответа после изменения
- **Реализовано:** что изменилось для пользователя.
- **Проверено:** какие тесты запущены и их результат (число passed/failed).
- **Приложение:** http://localhost:8501 — только после проверки доступности.
- **Ограничения:** что не проверено или не закончено.

## Карта кода
| Компонент | Файл |
|---|---|
| Загрузка TXT, кодировки, абзацы | `navigator/loader.py` |
| Тип документа, подпись, дата вступления в силу | `navigator/classifier.py` |
| Связь документов с договором | `navigator/linker.py` |
| Извлечение полей (реестр `FIELD_SPECS`) | `navigator/extractors.py` |
| Действующие условия на дату | `navigator/rules.py` |
| Проверка цитат и подсветка | `navigator/evidence.py` |
| Четыре вопроса | `navigator/questions.py` |
| Оркестрация | `navigator/pipeline.py` |
| Интерфейс | `app.py` |
| Тесты | `tests/` |

Новое извлекаемое поле — по `EXTENSION_GUIDE.md` (обычно одна запись `FieldSpec` + тест).

## Неизменяемые бизнес-правила
- Условия меняет только допсоглашение, подписанное обеими сторонами (по тексту) и вступившее в силу не позднее даты проверки.
- Письма и проекты не применяются, но показываются как несогласованные предложения.
- Имя файла, дата в имени и порядок загрузки не влияют на результат.
- Нет доказательства — «Требуется проверка»; нет значения — «Нет данных». Никаких догадок.
- Каждое значение имеет дословную цитату, имя файла и абзац; цитата проверяется на присутствие в исходном тексте.
- Запрещено хардкодить суммы, даты, ответы на вопросы и логику под STN-101/102/103.

## Прочее
- Язык общения и интерфейса — русский.
- Зависимости — только из `requirements.txt` (streamlit, pytest); новые добавлять лишь при явной пользе.
- Никаких API-ключей и секретов в репозитории.
